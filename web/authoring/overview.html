Different work. Different waits.

Understanding a codebase involves several kinds of work: reading source, asking models, following relationships, and checking answers. Attune makes those steps explicit so we can measure them, schedule independent work, and keep answers that are still valid.

Qwen retrieval: 33× lower known model spend

Qwen’s recorded embedding acquisition cost $0.141, versus about $4.65 estimated for frontier-model repository inspection across 88 tasks. Adding structural context and Jev judgment cost $0.165—28× below that estimate.

Qwen found a required file within ten on 85.9% of 85 eligible issues, versus 76.5% for the inspection arm. Sol was stronger at the first file and complete recovery. These workflows give models different work. The dollar comparison excludes computer costs; Sol’s subscription bill is unknown.

Cold acquisition made 351 embedding requests; unchanged warm replay made zero. Warm wall time was not measured. Explore the cost comparison → · Follow reuse →

Does the extra structure help find the right files?

Localization asks which existing files an issue’s reference fix touches. The retained SWE-rebench-V2 comparison scored 85 eligible issues across 22 repository groups. Qwen orders candidates; Atlas adds structural context as post-processing; Jev judges the shortlist.

What changes when the task is review?

Could saved knowledge of a repository make review cheaper? ReviewBench tested that idea. A reviewer already starts with a code change and must find real defects and explain them; finding files became a smaller part of the job.

In the corrected check of 24 reserved tasks, ordinary access produced 18 valid findings, versus 17 with optional packets, counting final reviews and saved checkpoints. Across the pilot and later check, the packet tool refused all three calls. The setup did not show a cost-saving benefit. Results, corrections, and resource accounting →

Small programs you can inspect

Files define functions, files import files, and functions call functions. Attune turns those relationships into typed questions with exact answer sets and source witnesses. In localization, that structure supplies context for judging a retrieved shortlist.
