## ADDED Requirements

### Requirement: Strong common conventional workspace profile

Every arm SHALL receive audited Python-owned workspace tools for file/path
inspection, text search, edit/write, Git status/diff/commit, allowlisted
repository tests, bounded conventional commands, and structured submission.
Common setup SHALL create equivalent isolated exact-revision workspaces and
record both case reveal and workspace-ready timestamps.

#### Scenario: Start a conventional arm

- **WHEN** the baseline workspace is ready
- **THEN** it exposes all common workspace capabilities
- **AND** its ready timestamp is available for diagnostic discovery latency

### Requirement: Treatment is additive and cannot be reconstructed by shell

The Attune profile SHALL add all eight existing typed MCP operations without
human approval gates and SHALL not require use of any operation. The common
command environment SHALL deny `attune-mcp`, Joern, Maude, ast-grep, the
property runner, and equivalent raw subprocess/Nix access to conventional
arms.

#### Scenario: Conventional arm attempts a native tool

- **WHEN** its bounded command tool attempts to resolve a treatment binary or
  equivalent escape route
- **THEN** policy enforcement rejects the attempt and records the denial

#### Scenario: Attune agent chooses a mutating operation

- **WHEN** an Attune run elects to checkpoint, apply, promote, commit, or
  finalize within its isolated investigation
- **THEN** the Python pack invokes the existing typed MCP wrapper without a
  benchmark-specific approval gate

### Requirement: Corrected three-arm cold pilot

The initial cold campaign SHALL define conventional-single, conventional-swarm,
and Attune-single arms, each with no prior research. It SHALL run two motif
cases, two seeds, and all three arms for twelve cold calibration runs before
claims about capability leverage, swarm cost, or substitution are made.

#### Scenario: Materialize the cold campaign

- **WHEN** campaign fixtures are validated
- **THEN** the runner schedules exactly twelve cold calibration run definitions
- **AND** identifies C-versus-A, B-versus-A, and C-versus-B comparisons

### Requirement: Cold campaign interpretation

The twelve-run cold campaign SHALL be treated as an instrumentation-calibration
decision point, not a required positive result. It SHALL use snapshot
revalidation under writer authority and cancellation-safe terminalization, all
three arms, and two seeds. It SHALL preserve a cold Attune loss caused by
native-tool startup and SHALL not substitute warm-cache measurements for gross
product cost.

#### Scenario: Cold results are inconclusive

- **WHEN** no arm reaches trustworthy hidden-evaluator quality or evaluator
  calibration is unstable
- **THEN** the campaign report recommends fixture/evaluator improvement before
  tool ablation, topology expansion, or external-corpus claims

#### Scenario: Attune single substitutes for a swarm

- **WHEN** arm C matches or exceeds arm B hidden-evaluator quality with lower
  aggregate model cost
- **THEN** the report identifies the result as evidence to pursue tool
  ablations, additional motifs, and held-out repositories
- **AND** it does not infer a universal advantage beyond the measured cases

### Requirement: Cost, latency, coordination, and representation metrics

The system SHALL record aggregate prompt/completion tokens, provider cost where
available, model calls, repeated reads, duplicated experiments, conflicting
claims, synthesis work, tool failures, native timing, evaluator components, and
accepted-result rate. It SHALL report gross, discovery, model, and native
intervals and preserve warm CPG/cache labels separately. Swarm wall-clock
claims SHALL require recorded concurrent branch execution.

#### Scenario: Sequential swarm completes

- **WHEN** swarm roles did not overlap in recorded time
- **THEN** the report includes coordination and cost metrics
- **AND** does not describe the result as a parallel wall-clock speedup
