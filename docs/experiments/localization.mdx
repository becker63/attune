The original panel had 96 tasks in 24 repository groups. Runtime-limited exclusions left 88 tasks in 22 groups; 85 had eligible gold, containing 218 files. Eligible splits were development 50, calibration 20, and final 15. The small final split limits generalization.

Gold contains existing modified/deleted JS/TS paths, excluding new files and tests. Prediction never reads it. Ranking arms share a frozen 29,493-candidate universe.

## What the deterministic rows actually compute

The four deterministic arms use **fixed, hand-written scoring rules**, not BM25.
“Prior” means the starting score before structural evidence is added; it is not
a learned probability. For every candidate file, the historical implementation:

1. Lowercases the issue and file path, splits them into runs of letters, digits,
   or underscores, discards tokens shorter than three characters, and removes
   duplicates. It adds **one point per distinct issue token also present in the
   path**. It does not search the file body, count repeated words, apply inverse
   document frequency, or normalize by document length.
2. Resolves issue tokens to **anchors**: a token must name exactly one declared
   file basename (without its extension) or exactly one declared symbol under
   the selected exact-name policy. Missing or ambiguous matches add nothing.
   It adds **two points per anchor hosted by the candidate**: the named file
   itself, or the file that defines the named symbol.
3. In the facts arm, adds **one point per anchored file connected to the
   candidate by a direct import**, in either direction. This bonus uses file
   anchors; it does not first turn every symbol anchor into its owning file.
4. In the Theory arm, also adds **one point per materialized structural witness
   row connecting the candidate file to an anchor**. Here a witness is a result
   of a bounded query over the extracted relationships, such as a typed
   two-edge chain.

The cumulative scores are `P = path matches`, `PA = P + anchor bonuses`,
`PAF = PA + import bonuses`, and `PAD = PAF + witness bonuses`. Files sort by
score descending, then path ascending for ties. The table above includes all four deterministic arms.
All candidates remain in the ranking, including files with score zero.

For example, in an **illustrative** repository, an issue mentioning `total`
gives `src/total-utils.ts` one path-match point. If `total` names exactly one
symbol, defined in `src/pricing.ts`, the anchors arm gives `pricing.ts` two
points even though its path does not contain `total`. That is the extra
mechanism behind “issue-to-code anchors.” These historical anchors are names
resolved from issue text; later experiments also use “anchors” for Qwen's
highest-ranked files, a different procedure.

### What “Theory” contributed in this experiment

The archived experiment materialized a fixed family of typed single-edge and
two-edge queries over `defines`, `defined_in`, `imports`, `imported_by`, `calls`,
and `callers`. A query can, for example, follow a file to its declared symbols
and then to their callees. Its output rows carry the query identity and the
entities connected by that query. Ranking counts rows whose endpoints include
both the candidate file and an issue anchor. It does not ask a language model
to score those witnesses.

Two candidate anchor policies were compared on the development split: exact
symbol names, or exact names plus final dotted segments. Both had 19 top-ten
hits on the 50 eligible development tasks; declared order selected
`anchors-exact-name-v1`. The weights above were fixed; no BM25 parameters or
learned ranking weights were fitted.

These formulas explain the historical table. The current small `Theory` module
and live Studio have separate implementations and should not be credited with
these older measurements.

## What changed the direction

Anchors helped the lexical prior. More additive structure reduced top-one accuracy. Equal top-ten aggregates concealed gains and losses. Hosted judgment used structure differently, as context for decisions over retrieved candidates, and improved these cohort results.

The inspected Sol arm had 60/85 top-one hits but used a different answer protocol; its 20 read-floor failures stayed misses. It is not a ranking comparison under identical procedures.

## Costs and repeated judgments

Qwen acquisition reported $0.1409903; structural Jev judgment $0.023915388. Together they were about 28.2× below a $4.6544292 API-equivalent estimate for recorded Sol inspection. Sol actually ran on a subscription; its plan bill is unknown. Compute is excluded and quality was not matched.

Five observations of the lexical judgments had modest top-ten effects and did not establish free improvement from larger answers. The report retains unions and equal-size controls. [Cost receipts](https://atlas-live-five.vercel.app/costs.json).
