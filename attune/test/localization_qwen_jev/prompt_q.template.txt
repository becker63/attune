FROZEN JEV REQUEST — Q-CONTROL CONDITION (post-hoc exploratory hosted-Qwen ablation)

This template records the exact bytes of the frozen Q-control prompt identity. It
was fixed before any Q-pair provider outcome and never edited afterwards: no
prompt tuning, no invented confidence threshold, no second model and no
outcome-dependent retry. Its wording is matched to the A-control identity: the
same basic relevance rule and the same three outcomes, differing only in the
candidate's retrieval fields (the original hosted-Qwen rank and its exact cosine
similarity instead of the P+A rank and score).

PART 1 — the frozen scientific question (Q-control).

rule (the state's `rule` field):
Decide whether the candidate source file must be modified to fix this bug report. Use only the bug report text and the candidate file path.

state (JSON object, shared by every question of one task):
{"task":"{task}","bug_report":"{bug_report}","rule":"<the rule above>"}
  {task}       = the task's public instance_id
  {bug_report} = the first 2000 characters of the task's public problem_statement
                 (a deterministic prefix of the public catalog projection)

question instruction (string, one question per candidate):
Candidate file path: {path} (original Q rank {rank}, Q similarity {similarity})
  {path}       = the candidate's repository-relative path, exactly as the frozen
                 hosted-Qwen ranking records it
  {rank}       = the candidate's original rank in the frozen Q ranking
  {similarity} = the candidate's exact unquantized hosted-Qwen cosine similarity,
                 read from the frozen `similarity_Q.tsv` sidecar

The Q-control condition carries ONLY the task/public issue, the candidate path,
the original Q rank and the exact Q similarity. It physically carries no
Repository, Theory, F, D, gold, patch, test, interface, oracle or final-metric
field, and it never reuses an A-pair judgment (the payload hashes differ).

outcomes (fixed names; one independent choice per candidate):
Relevant | NotRelevant | Unknown
A Failed(kind) transport, decode or validation outcome is never one of these and
is never mapped to a negative.

PART 2 — mechanical tool encoding (not scientific prompt content).
The installed jev-mcp server requires, per choice question, a `criteria` object
mapping each outcome name to a non-empty description string:
{"Relevant":"must be modified","NotRelevant":"must not be modified","Unknown":"insufficient information"}
