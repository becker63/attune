# Attune Oxlint Policy

`@attune/framework-oxlint-policy` is the Trellis-owned `effect-oxlint` policy
pack for Attune architecture invariants. It is not a broad Effect style lint
pack. Rules in this package should protect recipe-owned workflow, lifecycle,
receipt, projection, generated-artifact, and runtime boundary contracts.

## Clean-Fork Rule Promotion Plan

| Rule | Initial phase | Promote to error when |
| --- | --- | --- |
| `attune/no-public-script-workflow` | `warn` while remaining non-migrated packages still have package-local scripts | The migrated package roots have no live `scripts/` files, public Nx targets call typed source modules directly, and `workspace:no-compat-script-check` passes |
| `attune/recipe-owned-nx-target` | `warn` while ProjectionRegistry/Nx conformance is introduced and existing `check`/`repair` surfaces receive recipe or projection metadata | Public workflow targets are recipe-owned, projection-owned, or marked internal with a public parent |
| `attune/no-private-ledger` | `warn` while remaining Tend operational projections are audited | Tend session, command, long-job, token, tool, and wakeup rows expose recipe/run/receipt/observation IDs or bridge into `RecipeObservation`; fixture stores remain fixture-only |
| `attune/managed-recipe-requires-substrate` | `error` for newly authored ManagedRecipes, `warn` for pre-existing migration debt until upgraded | Existing ManagedRecipes declare lifecycle substrates or Alchemy bridge metadata, validation evidence, observed state or observation metadata, drift repair or rationale, and review gates |
| `attune/generated-artifact-owned-by-recipe` | `warn` for untouched generated debt while ownership is backfilled | Generated-looking TypeScript/CJS artifacts carry `@generated by recipe ...` headers or recipe/projection ownership, JSON generated artifacts are covered by recipe `allowedFiles`, and generation/freshness checks emit receipts or observations |
| `attune/no-raw-pg-outside-runtime` | `warn` while self-hosting policy fixtures and runtime adapter allowlists are narrowed | Runtime DB access is limited to Trellis runtime adapter/tooling boundaries, product packages use store/read-model services, and the live policy target passes with the rule at `error` |

Promotion is intentionally staged. The warning phase is for migration
visibility, not for permanent compatibility lanes. Invocation-only script
shims are not a final state; migrated roots must delete them and let the
no-compat workspace check fail any reintroduction. This change makes
`workspace:no-compat-script-check` hard enforcement for migrated roots; broad
oxlint rules remain warnings until the live `effect-oxlint-policy:policy`
target passes with each candidate rule at `error`. A rule should move to
`error` once the repository can pass without hiding workflow behavior in
scripts, `project.json`, private ledgers, generated files, or raw database
clients.

## Guardrails

- Keep `framework_core`, `framework_event`, and `framework_view` as the shared
  receipt/projection schema names.
- Route ManagedRecipe lifecycle through Effect Alchemy or an explicit existing
  substrate. Do not add custom lifecycle runtimes, planners, diff engines,
  schedulers, or observed-state stores.
- Defer ContextLens, ContextPacket, vector context selection, semantic
  compression, and agent memory to a separate change.
- Use `effect-oxlint` for Attune-specific policy before considering broad
  generic Effect lint rules.
