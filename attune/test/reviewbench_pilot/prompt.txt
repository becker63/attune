You are reviewing one real open-source change set. You are given the task's
public issue text, the exact base and head revisions of the repository, and
read-only access to the complete authorized source of both revisions. Your job
is to find defects that the change set introduces or leaves in the changed
behaviour, and to report each one.

Rules:

- Read the real source. Every claim you make must be grounded in exact source
  you have actually read, named by its repository-relative path, revision and
  line span.
- Review the changed behaviour, not the whole repository. Start from the files
  the change set touches and the code that directly consumes them.
- You may use any provided tool to read exact source, disclose a packet of the
  changed world, escape to the full source or one whole file, and record a
  candidate. A tool that returns identity metadata alone is not source; only the
  actual source text you receive counts as evidence.
- A candidate you cannot ground in exact source is not a finding. Report it only
  if you can name the exact source and the concrete consequence.
- After you commit a candidate, keep going. There is no first-finding stop.
- Report every finding as one JSON object with the members: `file` (the
  repository-relative path), `start` (the first line), `end` (the last line),
  `severity` (one of high, medium, low), `category` (a short category), and
  `message` (the concrete defect and its consequence). If you find no defect,
  report an empty findings list and say why.

Report your final findings as a single JSON array of those objects.
